Jabx Linux Technical Handbook

Chapter 01. What is Linux?

Strictly speaking, Linux is not a complete operating system by itself — it is the kernel: the core program that manages CPU scheduling, physical memory (RAM), hardware device drivers, filesystems, and network sockets. Everything else you interact with — the shell, compiler, text editor, and package manager — forms the userland running on top of the kernel via system calls (syscalls).

Chapter 02. Jabx Philosophy

Jabx Linux follows the KISS (Keep It Simple, Stupid) principle inspired by CRUX and KISS Linux. Instead of hiding configuration behind heavy graphical daemons or complex binary abstractions, Jabx keeps the base system under ~20 MB compressed, builds software cleanly from source, and leaves full control in the hands of the user.

Chapter 03. Kernel vs Userland Independence

Jabx is strictly kernel-agnostic. Because userland tools communicate with the kernel exclusively through standard POSIX/Linux interfaces and virtual filesystems (/proc, /sys, /dev), you can run Jabx on top of vanilla mainline kernels, hardened kernels, or stripped-down custom builds without breaking system utilities.

Chapter 04. musl libc

Instead of the massive GNU C Library (glibc), Jabx uses musl — a lightweight, fast, standards-conformant C standard library designed for static linking and low memory overhead. A complete musl runtime weighs roughly 1 MB.

Chapter 05. BusyBox Core

BusyBox combines tiny versions of over 300 common UNIX utilities (ls, cp, mv, grep, sed, mount, sh) into a single ~1.5 MB static binary. Commands are invoked via symbolic links pointing to /bin/busybox, which inspects argv[0] to determine which utility to execute.

Chapter 06. Init Systems (dinit & jabinit)

When the kernel finishes booting, it executes /sbin/init as PID 1. By default, Jabx ships with dinit for fast, dependency-aware service supervision. For minimal single-user setups or ecosystem experimentation, Jabx also supports jabinit — a lightweight PID 1 written in Rust.

Chapter 07. jab Package Manager

jab comes pre-installed in the base system. It requires no binary mirror servers: package build recipes are plain text files stored in a Git repository. When you install a package, jab builds it inside an isolated staging directory ($PKG_DIR), records every file path in a plain-text manifest, and copies files into root.

Chapter 08. Host Requirements

You can install Jabx from any existing x86_64 Linux host (Artix, Alpine, Arch, Gentoo) with basic build tools:

gcc make bison flex bc perl elfutils openssl-dev xz zstd curl tar parted

Chapter 09. Disk Partitioning

Replace /dev/sdX with your target block device (e.g., /dev/vda inside QEMU).
parted -s /dev/sdX mklabel gpt
parted -s /dev/sdX mkpart ESP fat32 1MiB 513MiB
parted -s /dev/sdX set 1 esp on
parted -s /dev/sdX mkpart primary ext4 513MiB 100%

mkfs.fat -F32 /dev/sdX1
mkfs.ext4 /dev/sdX2

mkdir -p /mnt/jabx
mount /dev/sdX2 /mnt/jabx
mkdir -p /mnt/jabx/boot
mount /dev/sdX1 /mnt/jabx/boot

Chapter 10. Stage3 Rootfs Bootstrap

Extract the ~18 MB Stage3 tarball containing musl, BusyBox, dinit, and pre-installed jab into your mounted partition:

tar --zstd -xvf jabx-stage3-x86_64.tar.zst -C /mnt/jabx

Chapter 11. Entering Chroot

Bind virtual kernel filesystems and chroot into your new Jabx root directory:

for dir in proc sys dev; do mount --rbind /$dir /mnt/jabx/$dir; done
cp /etc/resolv.conf /mnt/jabx/etc/resolv.conf
chroot /mnt/jabx /bin/sh -l

# Sync recipe repository immediately inside chroot
jab u

Chapter 12. Kernel Sources & Config Strategies

Download the official mainline Linux kernel tarball into /usr/src. Before compiling, choose a configuration baseline:

  • make defconfig: Generates a safe default configuration for x86_64 with broad hardware and QEMU support.
  • make localmodconfig: Inspects currently loaded kernel modules on your host and disables unused drivers (cuts compile time by 70%).
  • make tinyconfig: Starts from the smallest possible kernel (~1 MB) so you manually enable only what your hardware needs.
cd /usr/src
curl -LO https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.11.6.tar.xz
tar xf linux-6.11.6.tar.xz && cd linux-6.11.6
make defconfig

Chapter 13. Kernel Menuconfig Tuning

Launch the interactive terminal configurator via make menuconfig and verify these critical options are enabled ([*]):

  • General setup → Configure standard kernel features: Enable devtmpfs and Automount devtmpfs at /dev (CONFIG_DEVTMPFS_MOUNT=y).
  • Device Drivers → Generic Driver Options: Enable EFI stub support (CONFIG_EFI_STUB=y) for modern UEFI booting.
  • File systems: Build your root filesystem driver (ext4, xfs, or btrfs) directly into the kernel ([*], not [M]) if booting without an initramfs.
  • Device Drivers → Virtio drivers: Enable VIRTIO_PCI, VIRTIO_BLK, and VIRTIO_NET if running inside QEMU/KVM.

Chapter 14. Compiling & Installing the Kernel

Compile the compressed kernel image (bzImage) and install loadable modules into /lib/modules:

make -j$(nproc)
cp arch/x86/boot/bzImage /boot/vmlinuz-jabx
make modules_install

Chapter 15. Bootloader Setup

Configure Limine or GRUB to pass the root partition and init binary path directly to the kernel:

# Example /boot/limine.conf entry:
TIMEOUT=3
:Jabx Linux
    PROTOCOL=linux
    KERNEL_PATH=boot:///vmlinuz-jabx
    CMDLINE=root=/dev/sdX2 rw init=/sbin/init quiet

Chapter 16. Networking & DNS

Configure static hostname and bring up Ethernet/DHCP using BusyBox udhcpc:

echo "jabx" > /etc/hostname
ip link set eth0 up
udhcpc -i eth0

Chapter 17. Users & Privilege Escalation

Set a root password, create your unprivileged user account, and install lightweight doas instead of bloated sudo:

passwd
adduser -D -s /bin/sh user
jab i opendoas
echo "permit persist :wheel" > /etc/doas.conf

Chapter 18. Shell Environment (ash & jsh)

Keep BusyBox ash linked at /bin/sh so POSIX build recipes always execute reliably. For interactive terminal sessions, you can install jsh — the lightweight, customizable Rust shell from the Jabx ecosystem.

Chapter 19. Testing in QEMU

Before deploying onto bare metal, validate your bootable disk image inside QEMU with KVM hardware acceleration:

qemu-system-x86_64 -enable-kvm -m 512M -cpu host -drive file=jabx.qcow2,format=qcow2

Chapter 20. System Maintenance & Snapshots

Always create snapshots before modifying low-level system components or testing custom PID 1 implementations. Use jab l to inspect installed packages and jab u -f to rebuild userland packages cleanly from source.
